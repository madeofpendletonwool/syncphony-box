# ADR 0005: boxd — config, box bridge, setup and offline screens

- Status: Accepted
- Date: 2026-10-09
- Deciders: Phase 11 plan (MAD-797), boxd issue (MAD-803)

## Context

Stage 1 assembled the box out of scripts: a shell parser for
`syncphony.txt`, a kiosk wrapper, audio units. Stage 2 adds things that
outgrow shell scripts — a bridge the browser talks to (Syncphony
ADR 0016), a setup flow served to a phone, a start page that checks the
server before Chromium navigates. One daemon, `boxd`, now owns everything
on the box that isn't Chromium; CEC and the watchdog join it in stage 3.

## Decision

`boxd` is a small Go daemon: static (`CGO_ENABLED=0`), arm64, vendored
dependencies, built by `./build.sh` (from `git describe`, so
`boxd --version` is the box version) and installed by
`stage-syncphony/05-boxd`. Logs go to journald via stderr.

### Subcommands

- `boxd serve` — the daemon (also the no-argument default).
- `boxd config parse [FILE]` / `boxd config apply` — the boot config, taken
  over from the stage-1 shell script byte-for-byte: same warnings, same
  `config.env` output, same apply semantics (hostname from `name=`, the
  one-reboot `video=` cmdline sync), same `SB_TXT`/`SB_ENV`/`SB_CMDLINE`/
  `SB_HOSTNAME_CMD`/`SB_REBOOT_CMD` test hooks. `syncphony-box-config.service`
  (same name, same ordering) runs `boxd config apply` before avahi and the
  kiosk. `tests/syncphony-box-config.bats` still pins it — every assertion
  unchanged, only the binary under test moved.
- `boxd url` — prints the `/tv?box=<ver>&name=<name>` target for the kiosk
  wrapper (properly encoded), used when the daemon is down.
- `boxd --version` — the box version.

### Listeners

| listener | what | who |
|---|---|---|
| `127.0.0.1:8099` | the box bridge (`/v1/*`, Syncphony ADR 0016) + the kiosk screens: `/setup`, `/start`, `/status`, `/healthz` | Chromium on the box, curl |
| `:80` on the LAN | the phone setup form (one field: the server URL, plus the box's name) | a phone on the same network |

The LAN listener is the only thing exposed, and it is open **only while the
box is unconfigured**, or for 10 minutes after `SIGUSR1` (`SIGUSR2` closes
it; stage 3 wires the OK long-press to that signal). When closed it answers
404. It never offers anything beyond setting the URL and the name.

### The bridge (ADR 0016 exactly)

`GET /v1/info` → `{version, name, capabilities}`; `POST /v1/events`
(playing/paused/idle/paired/unpaired — logged, consumed by CEC and the
watchdog in stage 3); `POST /v1/heartbeat`; `POST /v1/reboot` and
`POST /v1/reload` (202, then `systemctl reboot` / `systemctl restart
syncphony-kiosk`). Requests carrying an `Origin` are refused unless it is
the configured server's origin; preflights are answered with
`Access-Control-Allow-Origin` and `Access-Control-Allow-Private-Network:
true` (Chromium's Private Network Access preflight). The bridge also
refuses any request whose `Host` isn't loopback, so a DNS-rebound name
can't reach it even with a matching-looking `Origin`. When unconfigured,
every origin is refused (there is no server to trust).

### The screens

- **Setup** (`/setup` on loopback, shown by the kiosk when `server_url` is
  missing or invalid): a big TV-readable page — dark, large type, a QR code
  for `http://<hostname>.local` (avahi) with the box's IP as fallback. The
  phone opens that address, gets the one-field form from the LAN listener,
  and boxd validates the URL by calling `<url>/healthz` itself before
  saving — a typo can't strand the box. Saving rewrites `syncphony.txt` in
  place (comments, BOM and CRLF preserved; the file stays the single source
  of truth), regenerates `config.env`, applies `name=` to the hostname, and
  restarts the kiosk, which then enters the server through the start page.
- **Start/offline** (`/start`): the page the kiosk opens whenever a server
  is configured. It asks boxd (`/status`) whether the server's `/healthz`
  answers and navigates to `/tv?box=<ver>&name=<name>` only when it does;
  otherwise it shows "Can't reach `<server>` — retrying" with the box's IPs
  and network state and a countdown, replacing Chromium's error page. The
  kiosk never navigates straight at the server while boxd is up.
- **The offline trigger.** With `/tv` open, a server that goes away leaves
  a live page (heartbeats keep coming) that can't reach its sockets. When
  the server stays unreachable for 2 minutes while heartbeats are fresh,
  boxd restarts the kiosk once, which lands it on the start page — the
  offline screen. It can't loop: after the restart there is no `/tv` page,
  so no heartbeats, so the condition can't re-arm until the server returns
  (and a 10-minute cooldown backs that up). This is the piece of the
  stage-3 watchdog policy needed to make the offline screen real; the rest
  (kernel watchdog, memory) stays in stage 3.

### Kiosk entry

The kiosk wrapper probes `http://127.0.0.1:8099/healthz` and enters through
boxd (`/start` with a server, `/setup` without). If boxd is down it uses
`boxd url` to navigate straight to the server, falling back to the static
`unconfigured.html` — the box degrades to stage-1 behavior, never to a
Chromium error page. `syncphony-kiosk.service` is ordered after
`boxd.service`, which is ordered after `syncphony-box-config.service`.

## Consequences

- The stage-1 shell parser is deleted; its unit and its tests stay, now
  running boxd. Nothing user-visible changes in the boot config flow.
- The image needs Go to build (build.sh cross-compiles arm64 from any
  host; CI's arm64 runner builds natively). The binary is not committed.
- `curl` and `ca-certificates` join the image packages (the wrapper probe,
  and boxd's HTTPS `/healthz` checks).
- Stage 3 adds CEC (key injection and the OK long-press opening the setup
  window), the hardware watchdog, and thermals in `/v1/info`; stage 4 adds
  update state to `/v1/info` and real remote care through
  `/v1/reboot`/`/v1/reload`.
